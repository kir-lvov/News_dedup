# Дедупликация новостных сообщений

Автоматическая группировка новостей, описывающих одно и то же событие, и выбор канонической новости для каждого кластера.

---

## Задача

Дан поток новостей из разных источников (агрегаторы, СМИ, телеграм-каналы). Одно событие часто публикуется в нескольких вариантах — с разными заголовками, переформулировками и деталями.

**Требуется:**
1. Сгруппировать новости, описывающие одно событие.
2. Устойчиво работать с перефразированием и разным порядком слов.
3. Не реагировать на незначительные отличия в деталях.
4. Для каждой группы выбрать каноническую новость (самую полную или раннюю).

**Вход:** таблица новостей с полями `id`, `title`, `text`, `source`, `published_at`.
**Выход:** `cluster_id` для каждой новости + флаг `is_canonical` для канонических.

**`ScoutieAutoML/russian-news-telegram-dataset`** — русскоязычные новости из Telegram-каналов.

| Параметр | Значение |

## Выбор подхода

Задача сводится к **кластеризации текстов в векторном пространстве**.

**Почему не TF-IDF + косинусная близость:**
- TF-IDF основан на частотах слов. Новости об одном событии могут использовать разные слова: «Путин встретился с Макроном в Париже» и «Президент РФ провёл переговоры с французским лидером» — общих слов почти нет, а событие одно.

**Почему не MinHash / SimHash:**
- Работают на пересечении n-грамм. Хороши для копипаста, но при перефразировании n-граммы меняются полностью.

**Почему не API-эмбеддинги (OpenAI, Cohere):**
- Требуют платного ключа, зависят от внешнего сервиса, не воспроизводимы локально.

**Выбранный подход: SentenceTransformer + косинусная близость + AgglomerativeClustering**

---

## Пайплайн

1. **Предобработка** — нижний регистр, удаление ссылок, утроение заголовка (усиление веса).
2. **Векторизация** — SentenceTransformer, нормализованные эмбеддинги.
3. **Матрица сходства** — косинусная близость между всеми парами.
4. **Временной фильтр** — сходство обнуляется для новостей с разницей >72 часов.
5. **Кластеризация** — `AgglomerativeClustering`, average linkage, `metric='precomputed'`.
6. **Каноническая новость** — самая длинная, при равенстве — самая ранняя.

## Сравнение моделей эмбеддингов

| Модель | Параметры | Размерность | Особенности |
|---|---|---|---|
| `paraphrase-multilingual-MiniLM-L12-v2` | 118M | 384 | Мультиязычная, русский — один из многих |
| `cointegrated/rubert-tiny2` | 29M | 312 | Русская, очень лёгкая |
| `ai-forever/ruBert-base` | 178M | 768 | Полноценный BERT-base для русского |

Перебор порогов 0.50–0.75, оценка по V-measure, ARI, AMI, NMI, FMI, Purity, CMR.

**Вывод:**
- **MiniLM** — кривая плоская, эмбеддинги плохо разделяют русские тексты. Не подходит.
- **rubert-tiny2** — самая быстрая, но 29M параметров не хватает для тонких семантических различий. Для прототипов.
- **ruBert-base** — оптимальный выбор: кривая пересекает эталон в диапазоне 0.70–0.75, V-measure стабильно выше аналогов.

## Результаты

**Финальная конфигурация:**

| Параметр | Значение |
|---|---|
| Модель | `ai-forever/ruBert-base` |
| Порог сходства | 0.74 |
| Временной фильтр | 72 часа |
| Кластеризация | AgglomerativeClustering, average linkage |
| Предобработка | Нижний регистр, удаление ссылок, утроение заголовка |

**Метрики на 5000 новостей (568 эталонных кластеров):**

| Метрика | Значение | Интерпретация |
|---|---|---|
| Предсказано кластеров | 575 | Отклонение от эталона: 1.2% |
| **V-measure** | **0.49** | Баланс чистоты и полноты |
| Homogeneity | 0.45 | 45% кластеров содержат одно событие |
| Completeness | 0.53 | 53% дубликатов одного события в одном кластере |
| **CMR (Canonical Match Rate)** | **0.59** | 59% канонических новостей корректно представляют кластер |
| NMI | 0.485 | Нормализованная взаимная информация |
| ARI | 0.008 | Штрафует за несовпадение количества кластеров |
| FMI | 0.020 | Геометрическое среднее precision/recall для пар |

**Сжатие:** ~8.7× — из 5000 новостей остаётся 575 уникальных событий.

**Почему метрики не 0.9+:**
- Эталонная разметка сделана вручную и может отличаться от семантической близости.
- Часть эталонных кластеров объединяет новости, которые модель считает разными событиями (и наоборот).
- При отклонении 1.2% по количеству кластеров V-measure 0.49 и CMR 0.59 — хороший результат для кластеризации текстов.

## Почему не K-means

| Характеристика | Agglomerative (наш) | K-means |
|---|---|---|
| Количество кластеров | Определяется порогом | Нужно задавать заранее |
| Метрика | Любая (`precomputed`) | Евклидова |
| Размер кластеров | Любой | Одинаковый |
| Временной фильтр | Встраивается | Невозможен |
| Детерминированность | 100% | Зависит от инициализации |
| Выбросы | Обрабатывает | Чувствителен |

В дедупликации новостей:
- Количество кластеров заранее неизвестно.
- Косинусное расстояние важнее евклидова.
- Кластеры сильно разного размера (от 1–2 до 30 новостей).
- Временной фильтр критичен и не встраивается в K-means.

## Масштабирование

Точная матрица сходства — O(n²) памяти. На 100K записей это ~80 ГБ.

| Объём данных | Метод | Память | Качество |
|---|---|---|---|
| До 10K | Точная матрица | O(n²) | 100% |
| 10K–500K | FAISS IVF | O(n·k) | ~95–98% |
| 500K–1M | FAISS HNSW | O(n·log n) | ~98% |
| Миллионы | Spark + LSH | Распределённая | ~90% |

В ноутбуке реализован вариант с **FAISS IVF** (раздел 5).

---

## Ограничения

- Точная матрица сходства не масштабируется на >10K без FAISS.
- Временной фильтр 72 часа — эвристика, может требовать настройки под источник.
- Общая модель, для узких доменов возможен fine-tuning.
- Эталонная разметка шумная — часть «дубликатов» на самом деле разные события.

---

## Возможные улучшения

- **Fine-tuning** модели на доменных данных (новости конкретного источника).
- **NER** — извлечение имён, локаций, организаций поможет разделять события с похожими формулировками.
- **Адаптивный временной фильтр** вместо фиксированных 72 часов.
- **Ансамбль моделей** — ruBert + E5 для устойчивости.
- **Cross-encoder реранкинг** — быстрый би-энкодер для отбора кандидатов + точный кросс-энкодер для финального решения.

## Установка и запуск

### Локально

```bash
pip install -r requirements.txt
python -m notebook
```

Открой `notebook.ipynb` и выполни ячейки по порядку.

### Через Docker

```bash
docker build -t news-dedup .
docker run -p 8888:8888 news-dedup
```

После запуска в консоли появится ссылка `http://127.0.0.1:8888/?token=...` — открой её в браузере.
