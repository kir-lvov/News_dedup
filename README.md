# News Deduplication

Автоматическая группировка новостных дубликатов на основе семантической близости.

## Задача

Поток новостей из разных источников содержит множество перепечаток одного
события. Алгоритм группирует дубликаты в кластеры и для каждого события
выбирает каноническую новость — самую полную и раннюю.

## Подход

- **Модель:** `ai-forever/ruBert-base` — SentenceTransformer, 178M параметров,
  обучена на русском языке
- **Векторизация:** заголовок + текст, заголовок утраивается для усиления веса
- **Сходство:** косинусная близость между нормализованными эмбеддингами
- **Временной фильтр:** 72 часа — одинаковые тексты с большей разницей во
  времени считаются разными событиями
- **Кластеризация:** AgglomerativeClustering, average linkage,
  `metric='precomputed'`
- **Каноническая новость:** самая длинная, при равенстве — самая ранняя

pip install -r requirements.txt

## Запуск

```bash
python -m notebook
```

В Jupyter открыть `notebook.ipynb` и выполнять ячейки по порядку.

## Структура

```
src/
  config.py        - константы и маппинг колонок
  data.py          - загрузка и нормализация данных
  text.py          - предобработка текста
  embeddings.py    - обёртка над SentenceTransformer
  clustering.py    - кластеризация и временной фильтр
  metrics.py       - метрики качества (ARI, AMI, NMI, V-measure, CMR)
  deduplicator.py  - основной класс NewsDeduplicator
```

## Метрики

- Стандартные: ARI, AMI, NMI, Homogeneity, Completeness, V-measure, FMI, Purity
- Кастомная: CMR (Canonical Match Rate) — доля канонических новостей,
  правильно представляющих доминирующее событие кластера

## Результаты

На выборке 5000 новостей (568 эталонных кластеров):

| Модель | Порог | Кластеров | V-measure | CMR |
|--------|-------|-----------|-----------|-----|
| ruBert-base | 0.74 | 575 | 0.49 | 0.59 |

Отклонение от эталонного количества кластеров — 1.2%.

## Масштабирование

| Объём данных | Метод | Память |
|-------------|------|-------|
| До 10K | Точная матрица | O(n^2) |
| 10K–500K | FAISS IVF | O(n * k) |
| 500K–1M | FAISS HNSW | O(n * log n) |
| Миллионы | Spark + LSH | Распределённая |

Для больших объёмов используйте `compute_distance_faiss()` из ноутбука
(раздел 5).

## Ограничения

- Точная матрица сходства требует O(n^2) памяти, для 50K+ нужен FAISS
- Временной фильтр 72 часа может требовать настройки под источник
- Модель общая, для узких доменов возможен fine-tuning
